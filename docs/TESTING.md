# Проверки DirectLAN 0.3.3

В 0.3.3 исправлено ожидание допуска после принятия запроса владельцем. Локальные журналы прежней версии содержали только создание Wintun; сохранённый профиль владельца уже включал гостя, а гостевой интерфейс оставался в ожидании подписанного состава. Это подтверждает незавершённый обмен допуском, но не доказывает доступность UDP между провайдерами.

Новый служебный канал проверен на настоящих UDP-сокетах в обычном и маскированном режимах. Тест с двумя устройствами WireGuard подтверждает: служебный обмен проходит, но до допуска у гостя нет установленных пиров WireGuard, рукопожатия и передачи пользовательских данных. Проверены подмена, другая сеть, отражение, повторы, размер и ограниченная очередь.

Тесты допуска проверяют привязку cookie к источнику, участнику, nonce и секрету, фрагментацию, подпись, закреплённого владельца, версию, локальный ключ и назначенный IP. Применение подписанного допуска проверено на приостановленном профиле без создания Wintun. Неверные коды сохраняют прежний профиль. Простое обновление метаданных отделено от изменения разрешений; действующий адаптер при нём сохраняется. Новые журналы показывают этапы допуска, его подтверждение и результат проверки туннеля без записи кодов и приватных ключей.

Локально пройдены go test ./..., go vet ./..., проверка зависимостей, сборка Go Windows x64 и WPF. Проверены SHA-256 архива Wintun и цифровая подпись DLL.

Тест транспорта проверяет три устройства WireGuard через настоящие UDP-сокеты во всех шести направлениях. У каждой пары отдельные ключи. Отдельно проверены повреждение и отражение оболочки, другая сеть, удалённый участник, STUN на том же сокете и предел IPv6/UDP-пакета 1280 байт.

Тесты кодов проверяют подпись владельца, десять уникальных участников, ошибки допуска, подмену подписи, неверные адреса и ключи, неоднозначный JSON и ограничения размера. Проверены сохранность прежнего профиля при ошибке восстановления и отсутствие ложного зелёного статуса после остановки.

Отдельный локальный запуск с правами администратора проверил реальный Wintun. Владелец создал сеть, принял два запроса, оба гостя по очереди установили по два прямых пира и маршруты. Неудачное изменение локального ключа восстановило прежний туннель и маршруты. Временные адаптеры после теста закрыты.

Интерфейс проверен на состояниях владельца, ожидания допуска, нескольких участников и недоступной службы. Пинг отображается отдельно по каждому участнику.

Проверка трёх физических ПК в разных сетях, нагрузка CPU, скорость, поведение провайдеров и восстановление после сна ещё предстоят. go test -race не запускался, поскольку текущая сборка выполняется без CGO.

В версии 0.3.2 проверены сохранение паузы после перезапуска, повторное отключение и ошибки команд без сети. Изолированные процессы проверили повторный запуск окна, освобождение блокировки и восстановление после аварийного выхода. Интерфейс проверен в состояниях паузы, активной сети, ожидания допуска, десяти участников и недоступной службы.
